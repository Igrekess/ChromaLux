# Developer APIs and Interfaces — ChromaLux 0.6.5

This documentation describes the contracts that are actually present in the
ChromaLux 0.6.5 source tree. At this stage, ChromaLux does not provide an
HTTP/REST API, an SDK installed by the DMG, or a standalone third-party kit.

## Interface Map

| Surface | Version | Intended audience | Status in 0.6.5 |
|---|---:|---|---|
| Plug-in binary ABI | 9 | Team and partners | Strict C contract; recompile for every ABI change |
| Metadata transport | tied to ABI 9 | Plug-in authors | Active C ABI |
| Metadata JSON helper | no binary version | C++ authors | C++17 source API, not an ABI |
| Plug-in manifest | `cls.plugin.manifest.v1` | Team and partners | Parsed format; some fields are not yet gates |
| Tether service IPC | 1 | Camera provider authors | Internal local protocol, not a network API |
| Graph | writes v2, reads v1/v2 | ChromaLux tools | Internal persistent format, without a JSON Schema |
| Node registry manifest | `cls.node.manifest.v1` | Graph Editor | Generated payload, distinct from the installation manifest |
| Command-line tools | no global version | Development and QA | Build binaries, absent from the user DMG |

## Normative Sources

When a comment or an older plan diverges from the implementation, the public
headers, loader, serializers, and their tests take precedence:

- `chromalux_plugin.h`;
- `cls_metadata.h`;
- `cls_metadata_json.h`;
- `PluginManifest.cpp` and
  `PluginLoader.cpp`;
- `tether_ipc.h`;
- `GraphSerializer.cpp`;
- `NodeRegistryExporter.cpp`.

Files under `docs/plans/` and `docs/specs/` describe the intent or history of
a workstream. They are not the normative reference for version 0.6.5.

## Current Boundaries

- The host C++ classes (`Graph`, `Scheduler`, `PluginLoader`,
  `PluginRegistry`, etc.) are not a stable public API.
- `cls_composition_mode.h` is a targeted internal C++ contract, not a general
  SDK extension.
- Helpers under `src/plugins/builtin/common/` are reusable within the
  monorepo, but they are neither installed nor exported.
- The Python/LLM bridge has its own documentation in
  `services/cls-llm-python/README.md`.
- Photoshop interfaces, SCSP and XMP formats, caches, and SQLite databases
  are outside the scope of this initial API reference.

## Known Gaps

- no CMake `install()`/`export()` rule for producing a standalone SDK;
- no maintained example outside the repository;
- no JSON Schema or OpenAPI file;
- no versioned SDK package;
- no symbol reference generated by Doxygen, MkDocs, or an equivalent tool;
- the macOS trust policy is suitable for internal and partner plug-ins, but
  not yet for an independent third-party ecosystem.

These limitations are documented to avoid confusing an interface present in
the code with a promise of public compatibility.
